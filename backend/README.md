# Bank backend v6.1 — 프론트 협의 후 백엔드 5개 수정

`bank-backendv6.zip` 기반 수정본입니다. 변경 상세는 [v6.1 변경 안내](docs/V6_1_CHANGES.md), 실행 결과는 [v6.1 검증 결과](docs/VALIDATION_V6_1.md)를 확인하세요. 압축본의 `dist/bank-backend-0.1.0.jar`는 이 소스로 빌드한 실행 파일입니다.

v6 기반 설명: `bank-backendv5-final.zip`에서 API·가입·복구 정책을 정리했습니다. API 경로는 `/api/v2`로 통일합니다. 배포본 이름 v6과 API 버전 v2는 서로 다릅니다.

## v6.1 수정

1. 멱등키 오류 코드를 `IDEMPOTENCY_KEY_INVALID`로 통일.
2. 새 비밀번호 오류의 `field`를 `newPassword`로 통일.
3. 재인증 비밀번호 실패 제한과 전체 요청 제한 분리, `Retry-After` 반환.
4. 가입 성공·실패·재전송의 민감정보 없는 JSON 감사 로그 추가.
5. 가입 성공 재전송을 신규 요청 제한보다 먼저 처리.

## 기존 v6 변경

- 구 `/api/auth/**`, `/api/accounts/**`, `/api/transfers`, `/api/deposits` 경로 차단. 신규·기존 프론트 모두 v2로 전환해야 합니다.
- 회원가입에 이름, 필수 약관 동의, 모의 휴대폰 확인 권한을 요구합니다. 발송이 꺼져 있어도 인증을 생략하지 않습니다.
- 이름·입출금 계좌번호·계좌 PIN 확인 후 아이디 조회 또는 5분짜리 일회용 복구 권한 발급. 비밀번호 재설정·로그인 잠금 해제의 목적을 분리합니다. 복구 코드는 선택적인 보조 수단으로 유지합니다.
- 로그인 비밀번호 3회 실패 시 잠금과 기존 세션 폐기, 10분 유휴 만료, 세션 연장, 계좌 PIN 4회 실패 시 명시적 재설정 전까지 잠금.
- 입출금 계좌 개설 시 PIN·모의 상품 약관 필수. 확인되지 않은 기존 사용자의 개설·이체·예적금 거래 차단과 보완 경로 제공.
- 비밀번호/PIN 규칙 강화, 개인정보를 직접 수정하여 휴대폰 확인을 우회하는 경로 차단. 프로필 재인증 요청도 제한합니다.
- 암호화·해시 저장, 계좌 관리·조회·이체·예적금 기능을 유지합니다.

## 실행과 검증

Java 17, Maven 3.9 이상에서 `mvn test`, `mvn package`를 실행합니다. 직접 빌드한 실행 파일은 `target/bank-backend-0.1.0.jar`입니다. 아래 실행 예시는 ZIP에 포함된 `dist/` 파일 기준이며, 직접 빌드했다면 경로를 `target/`으로 바꿉니다. pom의 키는 테스트 전용 공개 값이며 실행 환경의 키로 사용하면 안 됩니다.

실행 환경에 서로 다른 무작위 32바이트를 Base64로 인코딩한 `BANK_ENCRYPTION_KEY`, `BANK_LOOKUP_KEY`를 설정합니다. 기존 암호화 데이터가 있다면 원래 키를 유지해야 합니다.

로컬 시연에서는 추가로 32자 이상 무작위 `BANK_DEMO_INBOX_KEY`를 설정하고 다음과 같이 실행합니다.

```sh
java -jar dist/bank-backend-0.1.0.jar --spring.profiles.active=demo,demo-verification
```

`demo`는 가상 초기 사용자·잔액과 모의 입금 API를 활성화합니다. `demo-verification`은 모의 인증번호 수신함을 활성화합니다. 기본 프로필에서는 발송이 비활성화되어 신규 가입의 연락처 확인 요청이 503으로 실패합니다. 연락처 없는 가입으로 우회하지 않습니다. 기본 H2는 메모리 DB이므로 종료 시 데이터가 사라집니다.

수신함의 `X-Demo-Inbox-Key`는 서버/개발자 전용입니다. 브라우저 코드에 포함하지 않습니다. 로컬 개발자가 수신함 API로 번호를 확인해 입력하거나, 별도의 시연용 접근 통제가 있는 서버 경유 화면을 연결해야 합니다. 이 ZIP에는 그 프론트 화면을 구현하지 않았습니다.

### 새 메모리 DB에서 제공되는 시연 계정

| 아이디 | 로그인 비밀번호 | 이름 | 휴대폰 | 계좌번호 | PIN | 잔액 |
|---|---|---|---|---|---|---|
| alice | Demo!Alice7392 | 김시연 | +821090002951 | 2000000000000001 | 4826 | 100000.00 |
| bob | Demo!Bob5837 | 이시연 | +821090002963 | 2000000000000002 | 7391 | 50000.00 |

기존 DB에 같은 아이디가 있으면 덮어쓰지 않습니다. 위 값은 실제 개인정보가 아닌 새 로컬 시연 데이터입니다.

## 범위와 남은 제한

KB를 참고한 프로젝트 시연용 구현입니다. 실제 KB와 동일한 실명 확인·휴대폰 명의 확인·인증서·OTP·외부 은행 연동을 제공하지 않습니다. `SIMULATED`는 모의 확인이며 실제 본인 인증을 의미하지 않습니다. 로그인 비밀번호 길이는 프로젝트의 12~64자 정책을 유지합니다. 예적금 상품·이율·세금 계산은 기존 모의 정책을 유지합니다.

자동이체·공과금·외환·펀드·대출은 추가하지 않았습니다. 실제 PostgreSQL 인프라 통합은 마지막 단계로 남겨두었습니다. 이번 검증은 H2와 H2 PostgreSQL 호환 모드/Flyway이며 실제 PostgreSQL 검증이 아닙니다. 프론트엔드 코드는 수정하지 않았고, 프론트 요청에 대한 회신과 양쪽 코드 비교 문서는 다음 단계에서 작성합니다.
