# 5차 검증 결과

2026-10-02 별도 개발 작업 공간. Java17.0.20/Maven3.9.9/Spring Boot3.5.5. `mvn package` 성공, 테스트77건 실패0/오류0/생략0, 실행 가능한 JAR 빌드 성공.

## 구성

기존60건 + 신규8개 시나리오를 기본H2/마이그레이션H2에서 각각 실행한16건 + 기본 프로필 비활성 검증1건.

- 가입: 필수 약관 버전, 동의 이력, 일회용 연락처 권한, 안정적인 가입 재시도, 다른 본문 충돌, 연락처 없는 가입.
- 모의 인증: 일반 응답에 코드 없음, 암호화/HMAC 저장, 모의 수신함 개발 키+요청 토큰, 5회 실패 저장/폐기, 재발송 제한과 이전 번호 무효화, 만료.
- PROFILE: 타인 권한 사용 차단, 전화번호 정규화, SIMULATED 표시, 실제 verified=false, 일반 프로필 변경 시 UNVERIFIED 초기화.
- 복구 코드: 5개 난수, 해시 저장, 일회성, 잔여 개수, 회전 시 이전 코드 폐기, 현재 비밀번호 확인.
- 비밀번호 복구: 아이디/코드 소유 일치, 이전 비밀번호 실패, 새 비밀번호 로그인, 모든 로그인/이체 승인/남은 코드 폐기, 잔액 유지.
- 비밀번호 변경: 기존 비밀번호 필수, 성공 시 현재 세션/코드 폐기.
- PIN 분실: 본인 계좌+본인 코드+로그인 비밀번호, 타인 코드/계좌 거절, 잠금/실패 초기화, 세션 폐기.
- 동시성: 같은 복구 코드로 두 복구 요청은 한 건만 성공. 비밀번호 복구/구 비밀번호 로그인 경합 후 이전 토큰 사용 불가.
- 일반 프로필: 모의 수신함404, 발급503. 모의 기능은 개발 프로필에서만 동작.

V1~V9 migration 파일9개는4차 작업본과 바이트 단위 동일하다. V10만 추가했고 H2 PostgreSQL 모드에서 Flyway/JPA validate를 통과했다. 원래 테스트와 함께 실행해 금융 처리/암호화/계좌 관리 회귀도 확인했다.

## 재현과 범위

루트에서 `mvn test` 또는 `mvn package`. 공개 테스트용 암호화 키는 Surefire에서만 주입한다. 모의 테스트의 수신함 키도 공개 fixture이며 실제 실행용 비밀이 아니다. 빌드 요약은 BUILD_STAGE5.txt.

실제 PostgreSQL, 운영 부하, 다중 서버/프록시, 사용자Windows PC, 실제 프론트, 문자·메일 발송은 검증하지 않았다. 실명/실연락처 인증도 구현하지 않았다. identity의 전역 DB 잠금은 정확성을 우선한 구현이며 배포 전 처리량과 잠금 세분화가 필요하다.

모의 인증 상태는 계정 복구에 사용하지 않는다. 모든 복구 코드를 잃었을 때 관리자 우회 복구는 제공하지 않는다. 기존 데이터의 약관 동의나 실제 연락처 인증 상태를 임의로 생성하지 않는다. 구 기본 가입 API가 남아 있으므로 모든 가입 경로에 새 약관 강제를 완료한 상태는 아니다.
