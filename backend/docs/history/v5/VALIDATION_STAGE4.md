## 검증 중 수정

일일 사용액 이전 SQL의 GROUP BY 및 날짜 변환이 H2에서 기대와 다르게 작동하는 것을 실제 데이터 테스트로 발견했다. 구조 변경은 V8 SQL로, 과거 사용액 집계는 V9 Java로 나눴다. V9는 JDBC OffsetDateTime을 Instant → Asia/Seoul 날짜로 변환하며, 사용자·거래시각 순으로 읽어 날짜별 합계를 기록한다. DB 세션 시간대의 DATE 캐스팅에 의존하지 않는다.

실패 주입 테스트는 특정 금액을 전역 거절하는 방식에서 테스트의 특정 preview만 거절하는 방식으로 수정했다. 앞선 정상 테스트 데이터와 충돌하지 않으면서 결과 저장 실패 이후 전체 롤백을 확인한다.

V1~V7 migration 파일7개는3차 작업본과 바이트 단위로 동일함을 확인했다. V8/V9만 추가한다.

## 재현과 한계

프로젝트 루트에서 `mvn package`. 테스트 키는 pom의 Surefire 공개 fixture로만 주입한다. 실제 실행에는 별도 키를 지정한다. `docs/BUILD_STAGE4.txt`에 최종 테스트/빌드 요약을 포함한다.

H2와 H2 PostgreSQL 호환 모드/Flyway/JPA validate로 검증했다. 실제 PostgreSQL 동시성·운영 데이터 이전·Windows PC·실제 프론트·실은행망은 검증하지 않았다. DB 인프라 통합은 합의대로 마지막 단계다.

PIN 상태와 실패 횟수는 DB에 저장하지만 step-up/수취인 요청 제한은 단일 서버 메모리 기반이다. 다중 서버에서는 공통 제한이 필요하다. PIN 분실 재설정, 강한 본인확인, 실제 OTP/인증서 인증은 후속 범위다. 단계형 비밀번호 재확인만으로 MFA를 구현했다고 보지 않는다.
