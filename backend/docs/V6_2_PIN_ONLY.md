# v6.2 — F6 즉시이체 · F10 예적금 모의가입 PIN 단독 승인

## 변경 범위

로그인 세션은 여전히 필요합니다. 거래 시 로그인 비밀번호를 다시 입력하는 단계만 제거합니다.

| 기능 | v6.1 | v6.2 |
|---|---|---|
| F6 즉시이체 승인 | 로그인 비밀번호 + 출금 계좌 PIN | 출금 계좌 PIN |
| F10 정기예금·정기적금 모의가입 | 로그인 비밀번호 + 출금 계좌 PIN | 출금 계좌 PIN |
| F7 출금 등록·일반 PIN 변경·한도 감액 | 로그인 비밀번호 승인 | 유지 |
| 적금 추가 납입 | 로그인 비밀번호 + 출금 계좌 PIN | 유지 |
| 예적금 해지 | 로그인 비밀번호 | 유지 |

## 프론트 변경

### F6 즉시이체

1. 기존 수취인 확인 및 `POST /api/v2/transfers/previews`를 유지합니다.
2. 승인 화면의 로그인 비밀번호 입력란을 제거하고 출금 계좌 PIN만 받습니다.
3. `POST /api/v2/auth/step-up` 요청에서 `password`를 보내지 않습니다.

```json
{"purpose":"TRANSFER","targetId":"확인 응답의 previewId","pin":"출금 계좌의 4자리 PIN"}
```

승인 응답의 `authenticationMethod`는 `ACCOUNT_PIN`입니다. `actionToken`, `expiresAt`는 유지합니다.
4. 기존대로 `POST /api/v2/transfers`에 `{previewId,actionToken}`과 `Idempotency-Key`를 전달합니다.
5. PIN은 승인 단계에서만 전달합니다. 실행 요청 본문에는 넣지 않습니다.

### F10 예적금 모의가입

로그인 비밀번호 입력란과 `password` 전송을 제거합니다. PIN은 가입으로 돈이 빠져나가는 입출금 계좌의 비밀번호입니다. 새 예적금 계좌의 PIN을 만드는 과정이 아닙니다.

`POST /api/v2/savings`, Bearer 토큰 및 `Idempotency-Key` 필수:

```json
{
  "productId":"MOCK-DEPOSIT-12",
  "sourceAccountId":"출금 계좌의 accountId",
  "amount":"10000.00",
  "termsVersion":"MOCK-SAVINGS-2026-v1",
  "pin":"출금 계좌의 4자리 PIN"
}
```

정기적금은 `productId`에 `MOCK-SAVINGS-12`를 사용합니다. 응답 형태는 유지합니다.

## 오류와 제한

| 상황 | 처리 |
|---|---|
| PIN 누락 / 계좌 PIN 미설정 | 403 `ACCOUNT_PIN_REQUIRED` |
| PIN 형식 오류 | 400 `INVALID_INPUT` |
| PIN 불일치 1~3회 | 403 `PIN_INVALID` |
| PIN 4회 실패 및 잠금 이후 | 423 `PIN_LOCKED`; 연락처 확인 후 PIN 재설정 필요 |
| 이체 승인 요청량 초과 | 429 `RATE_LIMITED`, `Retry-After` 제공 |
| 예적금 가입 요청량 초과 | 429 `RATE_LIMITED`; `Retry-After`를 항상 제공하는 API는 아님 |

PIN 실패는 계좌 기준으로 누적됩니다. 즉시이체에서 1회, 가입에서 3회 틀려도 합계 4회 잠금입니다. 기존 PIN 정책대로 올바른 PIN 확인은 해당 계좌의 실패 횟수를 초기화합니다. 로그인 비밀번호 실패 횟수와는 별개입니다.

이체 승인과 F7 설정 승인은 사용자별 전체 요청량(최근 1분 30회)을 공유합니다. F7 비밀번호 5회 실패 차단은 F7에 적용되며 PIN 기반 이체 승인을 차단하지 않습니다. PIN 실패는 비밀번호 실패 제한에 추가되지 않습니다.

예적금 가입에는 사용자별 최근 1분 30회 요청 제한을 적용합니다. 기존 추가 납입·해지의 별도 인증 제한은 유지합니다.

## 유지되는 보호 장치

- 사용자·계좌 소유권, 연락처 확인 등 거래 자격, 계좌 상태·출금 등록·잔액·한도 검사
- 이체 preview 만료, 일회용 승인 토큰, preview·사용자·계좌 보안 버전 연결
- 실행 시 최신 상태 재검사, 트랜잭션 및 중복 요청 방지
- 잘못된 PIN으로는 승인 토큰·가입 계약·출금·성공 영수증 생성 안 됨
- PIN 변경으로 로그인 세션을 추가 무효화하지 않음; 기존 PIN 재설정의 세션 무효화 정책은 유지

## 구버전 프론트와 전환

F6/F10의 `password`는 호환용 선택 필드로 남기며 인증에는 사용하지 않습니다(기존 최대 64자 형식 제약 유지). 새 프론트는 필드를 생략하세요. F7의 `password`는 계속 필수입니다.

성공한 예적금 가입의 멱등 해시에는 요청 필드가 포함됩니다. 구버전에서 보낸 요청의 결과가 불명확하면 기존 키와 기존 본문 전체를 유지하세요. 재전송 도중 `password`만 제거해도 다른 요청으로 판단될 수 있습니다. 기존 성공 영수증의 저장 구조는 바꾸지 않았습니다.

DB 마이그레이션 추가는 없습니다. 배포 이름만 v6.2이며 API 경로는 `/api/v2`입니다. 이전 v6.1 문서의 F6/F10 비밀번호 승인 및 공유 비밀번호 실패 제한 설명보다 이 문서를 우선합니다. 프론트 소스는 이 배포본에 포함하거나 수정하지 않았습니다.

## 공동 검수

1. 로그인 비밀번호 입력 없이 즉시이체, 정기예금 가입, 정기적금 가입 성공.
2. PIN 1~3회 오류 안내, 4회 잠금, 올바른 PIN이라도 잠금 중 거부.
3. 이체와 가입 간 PIN 실패 횟수 공유, 실패 시 잔액·가입 목록 불변.
4. F7 비밀번호 누락 거부, 추가 납입·해지는 기존 인증 유지.
5. 동일 키·동일 본문 재전송 시 최초 결과 반환 및 한 번만 출금.
6. 이체 승인 응답 유실·실행 응답 유실을 구분하고 실행 재시도에는 기존 키·본문 유지.
